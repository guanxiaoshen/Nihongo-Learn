# Nihongo-Learn 产品理念与功能扩展规范

> 版本：1.0
> 更新日期：2026-08-28
> 适用范围：动词、形容词、副词、名词、助词及其他日语语法规则模块

## 一、产品是什么

Nihongo-Learn 是一个面向中文学习者的**日语规则图谱**。

它要解决的核心问题不是：

> 今天应该学习什么？还剩多少任务？

而是：

> 这条日语规则为什么这样变化或这样使用？我能不能看懂、记住并在新例子中复现？

因此，产品的核心产物不是题库、打卡系统或学习档案，而是：

```text
清晰的规则结构
  + 可操作的变化/选择路径
  + 真实而短小的例句
  + 易混点和例外
  + 规则后的即时回忆
```

## 二、产品边界

### 2.1 应该做什么

- 解释规则从什么形式或语义角色开始；
- 明确哪一部分发生变化，或哪个位置需要选择什么形式；
- 显示接续、句法位置和实际用途；
- 用代表词、代表句和对比例子帮助形成记忆；
- 将例外、限制条件和易混规则放在对应内容旁边；
- 用标签、分组和渐进展开降低信息密度；
- 提供很小的即时回忆题，帮助学习者检查刚刚看过的规则；
- 保留完整查询层，方便学习者需要时查全。

### 2.2 不应该做什么

- 不把产品扩展成每日任务、打卡或连续学习平台；
- 不以正确率、错题数量或学习时长作为产品中心；
- 不为了“看起来完整”而把所有术语和例外一次堆在首屏；
- 不只增加摘要卡片，却没有对应的详细变化/使用路径；
- 不用一个类别的例子代替其他类别的规则；
- 不把副词、助词等不同性质的语法项目强行套进“活用表”；
- 不在规则图谱的结构和内容未稳定前优先增加装饰主题。

已有的练习、统计和 `localStorage` 能力可以保留，但只能服务于规则理解和即时回忆。

## 三、学习者完成一个规则后应能回答什么

所有模块都要尽量让学习者回答下面四个问题：

1. **起点是什么？** 是词典形、词干、某个已变化形式，还是句中的语义角色？
2. **发生了什么？** 是词尾改变、后面接续、位置变化，还是意义范围发生限制？
3. **接下来怎么用？** 后面接什么、前后需要什么成分、表达什么作用？
4. **哪里容易错？** 有哪些例外、近似表达、固定形式或不能互换的情况？

对于不同语法类型，四个问题的具体含义可以不同：

| 内容类型 | 起点 | 发生了什么 | 使用重点 |
|---|---|---|---|
| 动词变形 | 词典形和动词类别 | 词尾换段、去る或特殊变化 | 接续和语气/时态/语态 |
| 形容词变化 | 词干和词类 | 去い、接だ系或其他后缀 | 谓语、定语、副词功能 |
| 副词用法 | 原词和修饰对象 | 形式转换或直接使用 | 修饰动作、程度、状态 |
| 助词 | 名词/句子成分的语义角色 | 选择对应助词并放到正确位置 | 格关系、话题、对比、语气 |
| 名词连接 | 名词和后续名词/谓语 | 接の、だ系或其他句型 | 所属、判断、修饰关系 |

## 四、记忆优先的内容层级

规则页面默认按照下面的顺序组织：

```text
模块说明
  ↓
一眼记忆公式/判断图
  ↓
标签或类别选择
  ↓
当前类别的详细路径
  ↓
最小对比例子
  ↓
例外和易混辨析
  ↓
规则后的轻量回忆
  ↓
完整查询表
```

### 4.1 一眼记忆层

这一层只回答“先记住什么”，不追求覆盖全部细节。

适合使用：

- 五段的 `あ・い・う・え・お` 变化轴；
- 形容词的两条核心公式；
- 助词按语义角色的分组图；
- 条件表达的前提来源对照；
- 一段动词“去る后直接接”的路径。

一眼记忆层必须同时出现必要的类别名称。例如动词不能只出现“五段”，还要明确：

```text
一类･五段动词
二类･一段动词
三类･カ变动词
三类･サ变动词
```

### 4.2 详细路径层

摘要不能代替解释。每个类别都要有自己的详细路径。

动词示例：

```text
二类･一段动词
食べる
  → 去「る」
食べ
  → ＋ない／ます／て／た
食べない／食べます／食べて／食べた
```

助词示例：

```text
动作的直接对象
  → を
本を読む
  → 对比“地点”不能直接套用
図書館で読む
```

详细路径至少要展示：

- 起点或语义角色；
- 操作或选择；
- 中间结果；
- 最终形式；
- 用途；
- 一个容易混淆的对照。

### 4.3 查询层

完整表格、术语索引和全部例子仍然要保留，但默认不应压过记忆层。

查询层适合：

- 复习时查某个形式；
- 比较多个类别；
- 查看完整术语；
- 检查例外；
- 为练习或写作寻找具体形式。

当前项目将完整 25 形动词表和六形形容词/名词表放进可展开区域，就是这一原则的应用。

## 五、统一规则区块模板

新增任何规则项目时，优先使用下面的内容模板：

```text
规则标题
  ├─ 学习者语言的用途说明
  ├─ 语法术语（辅助，不作为唯一标题）
  ├─ 起点/语义角色
  ├─ 变化或选择公式
  ├─ 分层结果：保留部分／变化部分／接续
  ├─ 代表例句
  ├─ 最小对比句
  ├─ 易错点/例外/限制
  ├─ 1–3 道即时回忆题
  └─ 完整查询入口
```

不是每个模块都必须机械显示全部字段，但不能缺少该模块真正需要的解释。比如助词没有“词尾变化”，就应改为“语义角色 → 助词 → 句中位置”。

## 六、视觉和交互语言

### 6.1 颜色表达信息角色

全站尽量保持以下语义：

```text
墨色：保留部分、词干、原始成分
主题色：发生变化或当前选中的部分
绿色系：接续、后缀、可继续连接的成分
警示色：例外、限制、容易误用的形式
辅助色：用途说明、术语和补充文字
```

颜色不能成为唯一信息来源。必须同时使用文字、边框、标签、符号或位置表达差异。

### 6.2 标签不是装饰

标签区的职责是降低信息密度，同时确保所有类别可达。

要求：

- 每个类别都必须是一级可选内容；
- 标签文字必须完整、明确；
- 选中标签后，详细内容、例句和派生结果都要同步变化；
- 不能只有标题变化，内容仍然固定使用另一类别的例子；
- 当前标签应有清晰的选中状态和辅助播报；
- 标签选择状态可以保存在会话中，但不能影响规则数据本身。

### 6.3 渐进展开

首屏先给核心记忆内容，复杂内容通过以下方式降低压力：

- 标签切换；
- 分组卡片；
- `details/summary` 查询展开；
- 行内锚点；
- 对比区块；
- 移动端单列布局。

## 七、如何设计不同类型的规则

### 7.1 变形型规则

适用于动词、形容词等有明确形式变化的内容。

核心结构：

```text
词类/类别
  → 起点
  → 变化操作
  → 接续
  → 结果
  → 用途
  → 例外
```

例如动词：

```text
一类･五段动词
書く → 書か＋ない → 書かない
```

### 7.2 选择型规则

适用于助词、条件表达、相似句型等不能简单归结为词尾变化的内容。

核心结构：

```text
语义角色/上下文
  → 可选形式
  → 句中位置
  → 典型例句
  → 最小对比
  → 不能互换的边界
```

不要把选择型规则伪装成一张“所有答案都能互换”的表。

### 7.3 句中功能型规则

适用于副词、定语、名词连接等内容。

核心结构：

```text
原词类
  → 修饰对象
  → 连接形式
  → 例句
  → 与谓语形式的区别
```

例如：

```text
い形容词 + 名词：高い本
い形容词 + 动词：早く話す
な形容词 + 名词：静かな部屋
な形容词 + 动词：静かに話す
名词 + 名词：学生の本
```

副词是句中功能，不应被误认为和动词活用、形容词活用属于同一种分类。

## 八、以“助词”作为未来扩展时的执行范例

助词模块应遵循规则图谱理念，但不应复制动词活用表的结构。

### 8.1 推荐的信息架构

```text
助词总览：先按语义角色分组
  ↓
当前角色的核心公式
  ↓
助词标签：は／が／を／に／で／へ／と／も……
  ↓
当前助词的句中位置和典型用法
  ↓
最小对比：は vs が、に vs で、に vs へ……
  ↓
特殊用法和限制
  ↓
轻量判断题
  ↓
完整助词查询表
```

### 8.2 标签分组建议

第一版不宜按五十音平铺所有助词，可以按学习者要表达的关系分组：

- 话题、对比与强调：`は`、`も`；
- 主语和状态：`が`；
- 动作对象：`を`；
- 时间、目的地、对象、存在位置：`に`；
- 动作发生地点、工具、原因：`で`；
- 方向和移动目标：`へ`、`に`；
- 共同、引用、变化结果：`と`；
- 所属和名词连接：`の`；
- 并列、范围、终助词等后续组。

分组只是记忆入口，不等于这些助词只有一种用法。每个助词仍要有自己的详细页面或区块。

### 8.3 单个助词的区块模板

```text
助词：で
核心作用：动作发生的地点、使用的工具/手段、原因或范围
位置：名词 + で + 动作/状态
例句：図書館で勉強します。
对比：存在地点通常用 に；动作发生地点用 で
限制：不能把所有“地点”都直接替换成 で
回忆题：図書館＿勉強します。
```

### 8.4 助词模块的关键原则

- 先讲“句子成分是什么关系”，再讲助词名称；
- 通过最小对比解释差异，不只列一堆例句；
- 一个助词有多个常见用法时，按用途分小组；
- 标出助词不能互换的边界；
- 例句要短，尽量只改变一个因素；
- 练习优先做“根据语义选择”，而不是机械背助词清单；
- 完整查询表作为查阅层，不作为唯一学习方式。

## 九、数据和代码扩展规范

### 9.1 数据职责

规则、例句、对比句和例外尽量放在 `data/`：

- 数据文件只描述内容，不负责渲染；
- 每条数据有稳定的 `id`；
- 类别、标签和显示文本分开保存；
- 例外和可接受变体显式配置；
- 不把同一条规则复制到多个页面的内联脚本中。

当前项目的参考文件：

- [data/forms.js](../data/forms.js)：动词形式、规则、例句和对比；
- [data/verbs.js](../data/verbs.js)：动词示例、词库和例外；
- [data/adj-noun.js](../data/adj-noun.js)：形容词/名词规则与词库。

未来助词可以使用类似的独立数据文件，例如 `data/particles.js`，但字段应服务于“语义角色和对比”，不必强行复用动词的 `formId`。

### 9.2 逻辑职责

- 变形计算放在 `js/` 引擎；
- 页面渲染负责组织记忆层、详细层和查询层；
- 数据校验应在页面初始化时尽早失败并显示明确错误；
- 继续保持 `<script>` 顺序加载，保证 `file://` 可运行；
- 不因为新增模块引入构建系统或不必要的依赖；
- 复用 `escapeHtml`、`ruby`、主题变量、焦点样式和现有交互模式。

### 9.3 类型和标签命名

面向学习者的标签要完整，不能只留下内部代号：

```text
一类･五段动词
二类･一段动词
三类･カ变动词
三类･サ变动词
```

内部 `id` 可以保持短小稳定，例如 `godan`、`ichidan`、`kuru`、`suru`。

### 9.4 练习和统计职责

规则模块的小练习应该：

- 紧跟对应规则；
- 每个区块原则上 1–3 题；
- 先让学习者回忆，再显示答案；
- 错误时说明词尾、接续、语义或例外；
- 不新增每日任务、学习计划或社交机制。

统计只用于辅助判断规则是否容易错，不应改变规则页面的核心结构。

## 十、新增功能的执行流程

任何新模块（例如助词）开始编码前，先完成以下步骤：

### 第一步：定义学习问题

用一句话说明学习者要学会什么：

```text
学习者看到一个句子成分后，能选择正确助词并解释为什么。
```

不要从“我要新增一个页面/一张表”开始。

### 第二步：确认规则类型

判断它属于：

- 变形型；
- 选择型；
- 句中功能型；
- 固定表达型；
- 混合型。

不同类型使用不同的“起点”和“变化路径”。

### 第三步：抽取最小记忆公式

先写出 1–3 条能在首屏记住的公式或判断原则。

例如：

```text
动作发生地点 → で
存在的位置 → に
```

如果公式无法覆盖全部情况，要同时写出边界，不要用过度简化的口诀误导学习者。

### 第四步：确定类别标签

所有类别都必须是一级可达内容。检查：

- 是否有某一类被误做成主角；
- 是否只有摘要，没有详细路径；
- 标签切换后内容是否真的变化；
- 标签名称是否对学习者完整可读。

### 第五步：准备最小例句和对比句

每个核心规则至少准备：

- 一个正例；
- 一个只改变关键因素的对比句；
- 一个易错或边界说明。

例句服务于规则，不要为了数量堆砌词汇。

### 第六步：设计轻量回忆

在规则后安排 1–3 道题，优先选择：

- 填空；
- 形式拆分；
- 类别判断；
- 最小对比选择；
- 找出不自然或错误的形式。

### 第七步：决定查询层

把完整内容放到可展开表格、索引或分组中，确保“想查时查得到”，但首屏仍然保持可记忆。

### 第八步：验证

至少验证：

- 内容数据完整；
- 每个类别都能到达；
- 代表例句与规则一致；
- 例外没有被普通规则覆盖；
- 移动端没有横向溢出；
- 键盘焦点、`ruby` 和主题样式不回归；
- 现有引擎和页面测试仍通过。

## 十一、反模式清单

以下情况应在代码审查或自检时直接退回：

### 反模式 1：只做摘要卡

```text
一段动词：去る后直接接
```

但没有展示：

```text
食べる → 食べ＋ない → 食べない
```

这只能算提示，不能算规则讲解。

### 反模式 2：类别标签只改变标题

点击“二类･一段动词”后，正文仍然显示 `書く → 書かない`，说明标签没有真正驱动内容。

### 反模式 3：把所有内容平铺在首屏

完整表格可以保留，但不能让学习者先面对几十行术语，再自己寻找核心规律。

### 反模式 4：用一个类别代表所有类别

五段、一段、来る、する的变化方式不同；助词也有不同语义边界。任何主视觉示例都不能隐瞒类别差异。

### 反模式 5：只讲“能不能用”，不讲“为什么”

尤其是助词和条件表达，必须展示语义角色、句中位置和最小对比。

### 反模式 6：把副词或助词强行当作活用

如果内容本质是句中功能或形式选择，应使用对应的信息结构，不要为了表格对齐而牺牲概念准确性。

## 十二、功能验收清单

### 内容

- [ ] 学习目标可以用一句话说明；
- [ ] 规则公式或判断原则足够短且不误导；
- [ ] 每个类别/标签都有详细内容；
- [ ] 起点、变化/选择、接续/位置和用途清楚；
- [ ] 至少有代表例、对比例和易错说明；
- [ ] 例外和限制放在相关规则旁边；
- [ ] 术语是辅助，不替代学习者语言。

### 记忆

- [ ] 首屏先看到核心规律；
- [ ] 结果和过程同时可见；
- [ ] 视觉层级能区分保留、变化、接续和例外；
- [ ] 规则后有 1–3 道即时回忆题；
- [ ] 学习者可以先回答，再查看答案和解释；
- [ ] 不需要依靠每日任务才能使用该模块。

### 交互

- [ ] 所有类别都能通过标签或分组到达；
- [ ] 选中标签后内容确实同步更新；
- [ ] 完整查询层可以展开和收起；
- [ ] 状态播报和键盘焦点清楚；
- [ ] 移动端内容可读，不出现意外横向溢出。

### 工程
